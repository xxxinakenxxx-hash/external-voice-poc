# 【営業AIメモ】実装指示書 MAIL-02｜朝メール改修・北九州対応

作成日：2026-11-04／状態：指示書作成・実装未着手  
前提：MAIL-01の証拠付き調査完了、対象ファイルと権限・管轄の判定方法についてユーザー承認済み。

## 1. 目的・対象
現行`runMorningBriefing`を維持し、既存`sales`向け朝メールの内容を壊さず`manager`・`president`向けに配下活動まとめを追加する。同じ工程内で北九州の地域判定と天気・交通表示・地域別配信集計を是正する。**旧日次メール廃止はMAIL-04、週間メールはMAIL-03**。

## 2. 変更対象候補（MAIL-01で実在・影響を確認後に確定）
- `src/09_morning_brief.gs`：対象ロール、地域判定、役職別の本文生成、北九州天気／交通なし、地域別ログ。
- `src/06_output.gs`：既存の日次集計ロジックを**必要な場合だけ**参照・再利用する最小改修。旧日次送信をまだ削除・停止しない。
- 権限・所属判定関数、`output_config`、`user_master`等の参照は現行定義を尊重する。**新規DB列・シート、role変更、関数名変更は独断禁止**。
- 他ファイルが必要なら理由を示して停止し、変更対象追加の承認を得る。

## 3. 確定仕様
- `sales`：現行の本人向け天気・地域別交通情報・要対応まとめを維持。
- `manager`：本人向け朝メール＋同じ営業所に所属する営業担当者全員の活動まとめ。
- `president`：本人向け朝メール＋管轄会社の配下活動まとめ。会社・営業所の対応が不明なら他社情報を推測で含めず停止。
- 配下の対応事項は`deal_records`から抽出・要約。他人の`todo_tasks`を取得しない。
- 旧`daily_manager`の必要な情報を朝メールに統合するが、同一要素の重複表示を避ける。配信日と7～8時台は現行を維持。
- 北九州：有効な対象者の朝メールに北九州の天気。交通情報欄なし。地域別`delivery_daily_log`にも北九州を正しく分類し、既存送信と二重に出さない。
- `MailApp.sendEmail`結果とメール到達は分けて記録。

## 4. 実装前の必須照合・停止
- MAIL-01で確定した対象者・権限・管轄・既存朝メール全文を確認する。
- 旧日次から統合する項目を元コード・メール例と突合する。
- ローカルにGit未追跡の`src/09_morning_brief.gs`、未コミット`src/06_output.gs`等がある場合は、その内容を破棄せずGAS現行版と照合する。
- 当該差分が特定できない、マスタ不足、権限不足、既存配信を壊す可能性がある場合停止。
- 本工程での`president`本人ToDo権限変更を予定しない。週間メールの本人ToDo課題はMAIL-03の着手判断へ明示引継ぎ。

## 6. 反映・停止・ユーザー確認
- 変更範囲を承認後、最小差分の実装と静的・隔離検証を実施。構文エラー、指定外差分、GAS対象版との不一致があれば停止。
- `clasp push --force`は**別途反映承認があり**対象外差分を巻き込まず安全に反映できる場合のみ。トリガー、デプロイ、実メール送信は別承認。
- 旧日次メールは廃止しない。`TASK_CURRENT.md`更新は許可されたローカル工程記録に限り、GitHubへ直接同期したものを正本扱いしない。
