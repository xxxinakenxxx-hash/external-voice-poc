## 3. 改修後の業務仕様
### 3.1 朝メール
- 対象：有効な`sales`、`manager`、`president`。現行の平日午前7～8時台を維持。
- `sales`：現行の天気・対象地域の交通情報・本人向けまとめ／要対応事項を維持。
- `manager`：本人向け朝メール＋所属営業所の営業担当者全員の活動まとめ。
- `president`：本人向け朝メール＋管轄会社の配下の活動まとめ。
- 配下の対応事項は商談記録から抽出する。他人の`todo_tasks`は参照しない。旧日次メールの必要情報を朝メールへ統合するが、重複表示は避ける。
- 北九州：北九州の天気、交通情報なし。既存の送信実績を踏まえ宛先・地域判定・ログの欠落を検証し、重複送信を防ぐ。

### 3.2 旧日次メール
- `daily_manager`を、朝メールへの統合が検証された後に廃止する。
- 過去ログは保持する。共用関数を参照関係未確認のまま削除しない。実際の廃止はMAIL-03。

### 3.3 週間メール
- 対象：有効な`sales`・`manager`・`president`。月曜日午前8時台（JST）。
- 「先週」：前週月曜日～日曜日。「今週」：当週月曜日～日曜日。
- 先週の集計範囲：`sales`本人、`manager`本人＋所属営業所の営業担当者全員、`president`管轄会社全体。
- 今週の予定・計画：**全役職とも本人の商談記録にある予定＋本人のToDo期限のみ（暫定仕様）**。他人の予定・ToDoは使用しない。
- 本文5項目：①先週の活動実績（商談・訪問・電話）②先週の主な商談（全役職最大5件）③先週の進捗・課題 ④今週の予定・計画 ⑤本人の未完了ToDo。
- 重要商談の選定順：緊急対応→重要な商談の進展→失注・停滞の懸念→今後の営業機会。根拠レコード・理由を残し、存在しない事実を生成しない。
- `president`は全社集計を維持しながら、営業所別の実績内訳、重要商談最大5件、進捗・課題最大5件に圧縮する。本人の今週の予定・本人ToDoは別扱い。
- 本人ToDoは今週期限・期限超過・期限なしを区分し、保存値（内容・期限・重要度）を原則そのまま表示。
- 商談件数と活動回数を区別し、1入力のAI分割で訪問・電話を重複計上しない。判別不能なら推定数を実績として表示しない。
- Googleカレンダーは使用しない。日付未確認の対応事項を今週予定へ捏造しない。
